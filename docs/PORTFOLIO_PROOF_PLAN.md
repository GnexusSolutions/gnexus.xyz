# Portfolio Proof Plan

This plan cross-references the 52-job search by capability family. Its purpose is to turn transferable experience into inspectable evidence without inventing credentials, tenure, metrics, or customer results.

## P0 — Publish first

### 1. Customer implementation room

Build a small working implementation environment for a fictional but realistic B2B workflow.

Required evidence: discovery notes, success definition, implementation plan, stakeholder map, requirements, decision log, risk/issue/assumption/dependency register, workflow demonstration, user-acceptance test, training guide, go-live checklist, closeout receipt, and unresolved limits.

Proves: implementation management, customer onboarding, project coordination, stakeholder communication, testing, training, and handoff.

### 2. Customer success operating simulation

Create a 90-day post-sale journey for the same fictional customer.

Required evidence: customer goals, adoption milestones, success plan, health model using clearly labeled simulated data, escalation scenario, QBR narrative, renewal-risk diagnosis, and expansion opportunity without fabricated revenue.

Proves: adoption thinking, customer guidance, risk identification, executive communication, retention logic, and cross-functional coordination.

### 3. Live AI workflow canary

Demonstrate one bounded AI-assisted operating workflow from intake to receipt.

Required evidence: objective, authority boundary, inputs, data classification, states, human approval, failure handling, cost, latency, output artifact, tests, correction path, and completion receipt.

Proves: AI operations, workflow design, product operations, technical translation, verification, and human-in-the-loop governance.

## P1 — Publish next

### 4. Redacted contract-readiness system

Use synthetic documents and clearly label them. Include intake, document register, custody, authorized review routing, version history, missing information, signature readiness, execution state, and follow-through.

### 5. Field-to-office service packet

Create a complete service-delivery example based on generalized installation conditions, with no client-identifying information. Include site readiness, access, material state, crew plan, vendor dependency, issue log, customer update, punch list, safe mock photo placeholders, and closeout receipt.

### 6. Community program journey

Create a privacy-safe participant journey for a housing or community-service process. Include eligibility boundary, consent, intake, barriers, service coordination, partner handoffs, status, recourse, and outcome evidence.

## P2 — Evidence that requires real participation

These items cannot be honestly manufactured as portfolio simulations:

- owned renewal or net-revenue-retention outcomes;
- formal enterprise SaaS account portfolio size;
- Fortune 500 implementation history;
- production customer adoption metrics;
- named-platform mastery without actual use;
- professional licenses or security clearances;
- confidential customer artifacts without authorization.

Use the portfolio to win a pilot, contract, volunteer implementation, or employed role that can generate authorized evidence.

## Publishing standard

Every proof object must state what is real, what is simulated, source and date, what the evidence supports, what it does not support, privacy and authorization state, current limitation, and next evidence needed.
