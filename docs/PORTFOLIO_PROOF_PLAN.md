# Portfolio Proof Plan — Cymatics Williams

This plan cross-references the 52-job registry by responsibility and proof burden. The purpose is to turn transferable experience into inspectable evidence without inventing credentials, tenure, metrics, or customer results.

## Already published as bounded case studies

1. Commercial Preflight — source, runtime, tests, exclusions, failures, fulfillment, and evidence.
2. Living Procedural Memory — intent, delta, divergence, recovery classification, and canary proof.
3. Contract Readiness — custody, authorized review, signature readiness, execution state, and follow-through.
4. Field-to-System Translation — site readiness, exceptions, ownership, customer updates, and closeout.
5. The Human-System Bridge — participant objective, accessible guidance, barriers, handoffs, recourse, and outcome boundaries.

## Priority proof object 1 — Customer implementation room

Build a small working implementation environment for a synthetic B2B workflow.

Required evidence:

- discovery notes and success definition;
- stakeholder map;
- implementation plan and timeline;
- requirements and decision log;
- RAID register;
- configuration or workflow demonstration;
- user-acceptance test;
- training guide;
- go-live checklist;
- closeout receipt and unresolved limits.

Proves: implementation management, onboarding, project coordination, stakeholder communication, testing, training, and handoff.

## Priority proof object 2 — Customer success operating simulation

Create a 90-day post-sale journey for the same synthetic customer.

Required evidence:

- customer goals and adoption milestones;
- success plan;
- health model with clearly labeled simulated data;
- escalation scenario and response;
- QBR narrative;
- renewal-risk diagnosis;
- expansion opportunity without fabricated revenue.

Proves: adoption thinking, customer guidance, risk identification, executive communication, retention logic, and cross-functional coordination.

## Priority proof object 3 — Public AI workflow canary

Demonstrate one bounded AI-assisted workflow from intake to receipt.

Required evidence:

- user objective and authority boundary;
- exact inputs and data classification;
- workflow states;
- human approval point;
- failure handling;
- cost and latency record;
- output artifact;
- verification tests;
- correction path;
- completion receipt.

Proves: AI operations, workflow design, technical translation, verification, and human-in-the-loop governance.

## Evidence that requires real participation

These items cannot be manufactured honestly as portfolio simulations:

- owned renewal or net-revenue-retention outcomes;
- formal enterprise SaaS account portfolio size;
- Fortune 500 implementation history;
- production customer adoption metrics;
- named-platform mastery without actual use;
- professional licenses or security clearances;
- confidential customer artifacts without authorization.

Use the portfolio to win a pilot, contract, volunteer implementation, or employed role that can generate authorized evidence.

## Publishing standard

Every proof object must state:

- what is real;
- what is simulated or generalized;
- source and date;
- what the evidence supports;
- what it does not support;
- privacy and authorization state;
- current limitation;
- next evidence needed.
