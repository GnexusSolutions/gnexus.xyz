Case study 02 · GOVERNED PRACTICE

Living Procedural Memory

A custody and recovery architecture for projects that evolve across long human–AI collaboration.

Stateful workflow · Recovery architecture · Source custodyEvidence-led case study

Context

What made this an operating problem.

Complex work degrades when every new message is treated as a reset. Decisions disappear, working artifacts are replaced, and confident summaries become detached from source reality. The system needed to preserve orientation without pretending to provide magical memory.

Operating problem

What had to remain true.

  • Long threads accumulated contradictory assumptions and version drift.
  • Working parts were repeatedly replaced by new interpretations.
  • Recovery required knowing the last aligned state and earliest divergence.
  • Humans needed a visible way to challenge claims and resume work.

Operating model

The structure introduced.

01IntentRecover the original outcome and boundaries.
02CustodyIdentify exact source and artifact state.
03DeltaTreat each message as a change, not a reset.
04ClassifyKEEP, REPAIR, REHOME, QUARANTINE, REJECT.
05CanaryRepair one end-to-end slice before expansion.

Evidence ledger

What the case proves—and what it does not.

Architecture

Project-custody files and gate behavior exist.

Does not equal universal autonomous memory.

Recovery

A defined intent/artifact/divergence method.

Does not guarantee every prior record is retrievable.

Registry

233 records identified and hash-bound.

Full per-record import remained pending at the recorded state.

Boundary

Authority and completion claims remain explicit.

Does not grant autonomous operational authority.

Truth boundary

A portfolio is only useful when its limits are visible.

Boundary

This case proves a governed architecture and working practice for custody and recovery. It does not claim universal memory, complete enterprise deployment, or authority beyond configured boundaries.

Role relevance

Where this proof transfers.

Program operations, AI workflow operations, implementation governance, product operations, documentation and knowledge systems.
